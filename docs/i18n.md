# Qoder Gateway Dashboard — Internationalization (i18n) Guide

## Overview

This guide describes the internationalization system for the Qoder gateway dashboard — a zero-dependency, drop-in JSON locale pack implementation that enables multi-language support without requiring code changes or build steps.

**Current Status**: v1 implements English (en) as the first integrated language, covering chrome and shell UI elements only. The log panel stream remains untranslated, with missing keys falling back to Chinese source text.

**Purpose**: Allow adding new languages by simply dropping a JSON file into the `i18n/` directory — any string not present in that file renders as Chinese source text, never blank or as a raw translation key.

---

## 1. What This Is

### Purpose

The i18n system provides a way to translate the dashboard interface without:
- Refactoring ~650 JavaScript call sites
- Introducing npm or Python dependencies
- Running a build step
- Modifying existing code structure

A language button appears in the header, immediately left of the theme selector. When selected, it loads a locale pack that maps Chinese source text to the target language.

### Design Principles

**DOM-Boundary Translation**: Instead of wrapping every string with `t('key')`, the system translates at the DOM boundary using an observer pattern. This means static HTML, JavaScript-generated content, and backend messages are all covered by one mechanism.

**Zero-Drop Coverage**: Any string not found in the locale pack renders as Chinese source text. Never blank, never shows a raw key like `"数据指标看板"`.

**Drop-in Language Packs**: Adding a language requires only dropping a JSON file into `i18n/`. No code changes, no registration, no rebuild.

**Backward Compatibility**: Malformed packs degrade gracefully to "no translations" without breaking the page. Unknown top-level keys in packs are ignored.

**Performance-First**: Memoized lookups, tiered matching strategies, and careful exclusion rules ensure the system doesn't impact the 5-second polling cycle used throughout the dashboard.

### Non-goals for v1

- No `t('key')` refactor of existing JS call sites
- No translation of the `/logs` freeform stream
- No full sweep of backend diagnostic prose
- No RTL support, plural/selectors, or per-locale number/date formatting
- No build step, npm dependency, or Python dependency

## 2. How It Works

### Four Lookup Tiers

The translation engine uses four tiers, checked in order from fastest-to-slowest:

**Tier 1: Exact Message Match**
```
Check `messages` object for exact key match
```
Fastest path — simple dictionary lookup for complete strings like `"数据指标看板" → "Analytics"`.

**Tier 2: Pattern Matching (with guards)**
```
Only attempted if the trimmed string contains CJK characters (a cheap gate that keeps plain labels from scanning the pattern list)
Scan `patterns` regex list left-to-right
```
For concatenated runtime strings like `"最近一次对话（12）走了 gpt-4：被自动换区"`. Slots `{0}`, `{1}` capture dynamic values.

**Tier 3: Fragment Match**
```
Check `fragments` object for exact key match
```
Shorter pieces like `" 个 Key 生效" → " keys active"`. Kept separate because whitespace matters.

**Tier 4: Identity Fallback**
```
Return original input unchanged
```
Guarantees nothing is ever blank. Chinese source text is preserved.

### Why Not `t('key')`?

Analysis of the codebase reveals why traditional key-based localization would fail:

- **75% of CJK characters** live directly in the JavaScript block
- **48% of 626 JS string literals** are fragments concatenated at runtime (`'累计消耗 ' + fmt(x) + ' Token'`)
- **~315 Chinese literals** arrive via backend `fetch` responses and render into toasts/errors
- A `t('key')` approach would touch ~650 lines, require ~1,100 invented keys, still miss all backend text, and break existing tests

**Solution**: Translate at the DOM boundary. The observer sees the *final rendered string*, so everything is covered additively by one mechanism.

### DOM Interaction Model

The system has three logical layers:

**Layer 2 (Core)**: Pure JavaScript, no DOM access. Exposes `QD_I18N.t(text)` function. Testable in Node.js without a browser.

**Layer 3 (Engine)**: The only layer touching the DOM. Uses:
- `TreeWalker` for initial page walk
- `MutationObserver` for dynamic updates
- Skips `.log-line`, `<code>`, `<pre>` elements
- Updates text nodes plus `title`, `placeholder`, `aria-label` attributes

**Layer 4 (Shell)**: Bootstrap logic handling:
- Pre-paint hydration from localStorage
- Language button dropdown rendering
- Cache management with version checking
- Manifest fetch and pack loading

## 3. Locale Pack Format

### Structure

Each language pack is a single JSON file named `{code}.json` where `{code}` matches the locale identifier (e.g., `en.json`, `ja.json`).

### Schema

```json
{
  "@locale": {
    "code": "en",
    "name": "English",
    "dir": "ltr",
    "order": 10,
    "version": 1
  },
  "messages": {
    "数据指标看板": "Analytics",
    "运行日志": "Logs"
  },
  "patterns": {
    "最近一次对话（{0}）走了 {1}：被自动换区":
      "Last conversation ({0}) used {1}: auto-switched"
  },
  "fragments": {
    " 个 Key 生效": " keys active",
    "（共": " (total "
  }
}
```

### Field Specifications

#### `@locale` Metadata

- **`code`**: Must match filename (without `.json`). Used for route matching and cache keying.
- **`name`**: Display name shown in language dropdown. Use native script (e.g., "English" not "英语").
- **`dir`**: Text direction. Currently reserved; set to `"ltr"` for all packs.
- **`order`**: Numeric sort order in dropdown. Lower numbers appear first.
- **`version`**: Integer cache invalidation signal. Increment on every pack change.

#### `messages` Object

Simple key-value pairs for complete strings. Keys are **verbatim Chinese source text**, trimmed. Values are translations.

Example:
```json
{
  "新建任务": "Create New Task",
  "保存更改": "Save Changes"
}
```

#### `patterns` Object

Key-value pairs where keys contain slot placeholders `{0}`, `{1}`, etc. The value can reorder slots freely.

Keys use regex-safe literal text with slots. The engine compiles patterns to regex:
```javascript
// Input: "最近一次对话（{0}）走了 {1}：被自动换区"
// Compiled: /^最近一次对话（([\s\S]+?)）走了 ([\s\S]+?)：被自动换区$/
// Slots: [0, 1]
```

Values interpolate captured groups:
```json
{
  "最近一次对话（{0}）走了 {1}：被自动换区":
    "Last conversation ({0}) used {1}: auto-switched"
}
```

Input: `"最近一次对话（12）走了 gpt-4：被自动换区"`
Output: `"Last conversation (12) used gpt-4: auto-switched"`

#### `fragments` Object

Partial strings, typically with leading spaces. Useful for suffixes appended to dynamic values.

Important: A leading space is part of the key! Example:
```json
{
  " 个 Key 生效": " keys active",
  " 个配额": " quotas"
}
```

Source: `"12 个 Key 生效"` → Output: `"12 keys active"`

### Matching Order

The four passes run in this sequence:

1. **Exact trim**: `src.trim()` against `messages` keys
2. **Whitespace collapse**: Collapse multiple spaces/newlines, then check `messages`
3. **Fragment exact**: Collapse then check `fragments` keys
4. **Pattern scan**: Attempt regex substitution if digit-or-length gate passes

**Critical**: Exact passes must come before pattern scanning. Otherwise, every whitespace-significant fragment loses to the catch-all pattern fallback.

### Slot Value Resolution

Slot values themselves can be translated recursively to depth 2:

Input: `"颜色主题：跟随系统 (当前浅色)"`
After messages: `"Color theme: 跟随系统 (当前浅色)"` ← half-translated
After slot resolution: `"Color theme: Follow system (current light)"`

Depth limit prevents infinite recursion when a pattern's source is only slots (`{0}`).

### File-Level Conventions

- **No index file**: The manifest scans the folder dynamically
- **No registration step**: Dropping a file makes it available immediately
- **Filename validation**: Must match `^[a-zA-Z0-9][a-zA-Z0-9._-]{1,31}\.json$`
- **Path traversal prevention**: No `..`, `/`, `\`, NUL, absolute paths allowed
- **JSON-only served**: Other files ignored even if present

### Examples

#### Simple label mapping
```json
{
  "@locale": {"code":"ja","name":"日本語","order":20,"version":1},
  "messages": {
    "数据指标看板": "データインジケーター",
    "用户管理": "ユーザー管理"
  }
}
```

#### Dynamic sentence with reordered slots
```json
{
  "patterns": {
    "{0}天内临期优先处理": "Priority for {0} days expiry"
  }
}
```
Source: `"7天内临期优先处理"` → Output: `"Priority for 7 days expiry"`

#### Fragment composition
```json
{
  "fragments": {
    "剩余": "remaining",
    " 配额": " quotas"
  }
}
```
Source: `"剩余5 配额"` → `"5 remaining quotas"`

## 4. Adding or Updating a Language

### Step-by-Step Workflow

**Step 1: Analyze Source Text**

Run the committed extractor to get a candidate list (requires Node.js + `acorn`):

```bash
python scripts/extract_i18n_keys.py
```

Then verify every chosen key with `tests/_test_i18n_packs.py`, which rejects any `messages` key that cannot be found in `dashboard.html` verbatim (or after the whitespace-collapse pass). That is what catches a mistranscribed key before it ships.

**Step 2: Draft the Pack**

Create `i18n/{code}.json`:
```json
{
  "@locale": {
    "code": "{code}",
    "name": "{Native Language Name}",
    "dir": "ltr",
    "order": {number},
    "version": 1
  },
  "messages": {},
  "patterns": {},
  "fragments": {}
}
```

Populate `messages` first with high-value chrome labels. Then add patterns for dynamic sentences. Finally, fragments for suffixes.

**Step 3: Validate Syntax**

Run pack validation:
```bash
python tests/run_all.py _test_i18n_packs
```

This checks:
- Valid JSON parsing
- `@locale.code` matches filename
- `@locale.version` is integer
- No key maps to itself (would cause loops)
- No catch-all pattern source (`{0}` alone)
- All keys reachable from `dashboard.html`

**Step 4: Test Locally**

Start the server and visit the dashboard:
```bash
python qoder_proxy.py
```

Open DevTools Console, verify:
- No parser errors
- Language button appears left of theme selector
- Dropdown lists your language
- Selecting it translates expected strings
- Chinese→target→Chinese roundtrip works
- Console shows zero i18n-related errors

**Step 5: Version Bump**

If updating an existing pack, increment `@locale.version`. This triggers cache refresh on all clients:

Old pack cached as v1. Editor adds 100 new keys but keeps version at 1. Repeat visitors get stale v1 cache — new keys look broken rather than missing. Increment to v2 → mismatch detected → refetch → reload once → consistent state.

**Step 6: Commit Files**

Ensure pack file is committed alongside code:
```bash
git add i18n/{code}.json
git commit -m "i18n: Add {Native Language Name} support"
```

Do not leave untracked — the `check_clean_checkout.py` script will flag it.

### Testing Checklist

Before marking a pack as ready:

- [ ] All Chrome UI elements translated (nav buttons, section titles, table headers, form labels)
- [ ] Theme dropdown labels translated
- [ ] Dynamic runtime strings (concatenated sentences) translated correctly
- [ ] Slot values resolved recursively (two levels deep)
- [ ] Whitespace-sensitive fragments correct (leading/trailing spaces)
- [ ] Fallback behavior intact (untranslated keys show Chinese)
- [ ] Cache invalidation works (version bump causes reload)
- [ ] Hidden tab edge case (rAF-only batching doesn't freeze state)
- [ ] First-visit flash acceptable (can be mitigated further if needed)
- [ ] No console errors or warnings

## 5. Runtime Behavior

### First Visit (No Cache)

1. Page loads in Chinese (source language, no pack required)
2. Paint completes (visible Chinese text)
3. DOMContentLoaded fires
4. Fetch `/i18n/manifest` to discover available languages
5. Detect user's preferred language (browser `navigator.language` or stored `qd-lang`)
6. If pack available, fetch `GET /i18n/{code}.json`
7. Hydrate L2 core with received messages/patterns/fragments
8. Run initial TreeWalker walk over document body
9. Observer starts watching for mutations
10. Visible switch from Chinese to target language

**Result**: One paint-flush event. Acceptable UX tradeoff.

### Cached Visit (v1+ User)

1. At parse time (before DOMContentLoaded), read `qd-i18n-pack` from localStorage
2. Synchronously hydrate L2 core from cached data
3. Walk document at DCL, before first 5s poll returns
4. Check `@locale.version` against manifest
5. If versions match, skip fetch entirely
6. Observer active from start

**Result**: No visible flash. Feels instant to repeat users.

### Language Switch

1. User clicks language button dropdown
2. Selects different locale code
3. Current tab reloads (`location.replace`)
4. New session begins as "First Visit" for that language
5. Subsequent visits use cache if version unchanged

**Note**: Reload required because `seen` WeakSet caches translated nodes — in-place swap would mix old/new renditions.

### Cache Invalidation

Version-based invalidation protects against partial updates:

**Scenario**: Editor adds 100 keys to en.json, forgets to bump version.
- Client has cached v1 pack
- `@locale.version` = 1, manifest reports 1
- No fetch triggered
- New keys invisible to user

**Fix**: Always increment version on content change. Document requirement in `i18n/README.md`.

**Pack Disappearance**: If server removes a language pack:
- Client detects version mismatch (or missing pack entirely)
- Drops stale cache
- Reloads into source language (Chinese)
- User can re-select if pack restored

### Hidden Tabs and rAF Batching

`requestAnimationFrame` does not fire when tab is hidden (`visibilityState='hidden'`). An rAF-only batching strategy would permanently freeze translation for backgrounded tabs.

**Solution**: Always arm a `setTimeout` fallback:
```javascript
let pendingWalk = null;

function scheduleFlush() {
  if (pendingWalk) return;
  requestAnimationFrame(() => flushWalk());
  setTimeout(() => flushWalk(), 100); // backup for hidden tabs
}
```

Whichever callback fires first drains the pending queue and nulls it. No double-walk, no extra state.

### Exclusions

These elements are skipped during walks:

- `.log-line`: Highest-volume mutation source; excluded to reduce cost
- `<code>`: Code snippets should preserve syntax-highlighted text
- `<pre>`: Preformatted blocks may contain non-translatable content
- `.no-i18n`: Manually marked exclusions via CSS class

Attributes excluded from translation: None currently — all text content plus title/placeholder/aria-label are fair game.

### Native Dialogs

Browser-native dialogs (`alert`, `confirm`, `prompt`) never pass through the DOM, so the observer cannot see them. The core wraps `window.alert`, `window.confirm`, and `window.prompt` once via `installDialogI18n`, translating only the first string argument and passing every other argument and the return value through unchanged. The wrapper is guarded by `window.__qdDialogI18n` so a repeated call cannot double-translate an already-English string. Non-string first arguments (for example a number passed to `alert`) are left untouched.

## 6. Server Routes

### GET `/i18n/manifest`

Returns discovered language packs:

```json
{
  "default": "zh",
  "packs": [
    { "code": "en", "name": "English", "dir": "ltr", "order": 10, "version": 1 },
    { "code": "ja", "name": "日本語", "dir": "ltr", "order": 20, "version": 1 }
  ]
}
```

**Behavior**:
- Scans `i18n/` directory at request time (no restart needed)
- Filters filenames by `I18N_FILE_RE` regex
- Reads metadata from each pack's `@locale` field
- Sorts by `order` then `code`
- Returns empty `{"packs": []}` if directory missing (never 500)

**Security**: Unauthenticated access required — login gate itself must be translated. Path validation critical here.

### GET `/i18n/{code}.json`

Returns raw pack file contents:

**Validation flow**:
1. Extract `{code}` from URL path
2. Match against `I18N_FILE_RE` → reject invalid names outright
3. Build safe path: `os.path.join(I18N_DIR, matched_name)`
4. Open file, read bytes
5. Verify `os.path.realpath(starts with I18N_DIR)` → prevent symlink escape
6. Return 200 with JSON body
7. On any error: return 404, never stack trace

**Headers**:
- `Cache-Control: no-store` (consistent with `_dashboard()`)
- `Content-Type: application/json`

**Security Model**

Attack surface: Unauthenticated route serving attacker-controlled path. Risks:
- Path traversal (`../../../etc/passwd`)
- Symlink escape (`i18n/symlink -> accounts/`)
- Arbitrary file disclosure (`.py`, `.env` exposure)

**Defense layers**:
1. **Regex allowlist**: Only filenames matching `^[a-zA-Z0-9][a-zA-Z0-9._-]{1,31}\.json$`
   - Anchored at both ends
   - Requires `.json` extension
   - Rejects `..`, `/`, `\`, NUL
2. **Safe path construction**: Match name first, then `os.path.join` — never concatenate user input
3. **Realpath containment**: After opening, verify canonical path stays within `i18n/`
4. **JSON-only service**: Ignore non-`.json` files entirely
5. **Error suppression**: Return 404, never expose internals

**Public-file caveat**: Translation files are public on the same port as the admin panel. They contain UI copy only. Do NOT put sensitive data in `i18n/`.

### Backend Implementation Notes

Locate handlers beside `_dashboard()` method in `qoder_proxy.py`:

```python
# Module constant near DASHBOARD_HTML definition
I18N_DIR = os.path.join(os.path.dirname(os.path.abspath(__file__)), "i18n")
I18N_FILE_RE = re.compile(r"^[a-zA-Z0-9][a-zA-Z0-9._-]{1,31}\.json$")

# Route dispatch before dashboard handler
if path == "/i18n/manifest":
    return self._i18n_manifest()
if path.startswith("/i18n/"):
    return self._i18n_pack(path[len("/i18n/"):])
```

Python 3.9 compatibility: Use `%`-formatting, avoid `match` statements, avoid `X | Y` annotations, don't rely on `str.removeprefix()` (introduced in 3.9).

## 7. Coverage and Limitations

### What Gets Translated

The system covers all strings originating from `dashboard.html`:

**Static markup** (directly in HTML):
- Navigation buttons
- Section headers (`<h2>`)
- Table headers (`<th>`)
- Form labels and options
- Button tooltips (`title` attributes)
- Accessibility labels (`aria-label`)

**JavaScript-generated**:
- `textContent` assignments composed at runtime
- DOM manipulation creating new text nodes
- `STAT_LABELS`, `KEY_ID_LABELS` mappings
- Toast message prefixes

**Backend messages**:
- Error toast text
- Notification bodies
- API response wrappers rendered client-side

### What Remains Backend Data

These elements stay in source language (Chinese) in v1:

| Element | Source | Reason |
|---------|--------|--------|
| Model catalog descriptions | `/v1/models` upstream payload | External provider metadata, not controlled by us |
| Agent Setup blurbs | `qoder_agents.py:668` | Backend control logic, outside pack scope |
| VM fingerprint fields | `/health` endpoint | Hardware/proxy telemetry data |
| Scheduler status modes | `mode_cn`/`mode_intl` in scheduler | Mode constants tied to backend workflow |
| Log stream entries | `/logs` route | Deliberately excluded from scope |

### Why Upstream Metadata Is Out of Scope

Model descriptions, provider metadata, and third-party labels originate from external APIs (`/v1/models`, `/health`, etc.). Translating these would require:
- Shipping translation packs with backend code (breaks drop-in contract)
- Server-side locale detection (couples HTML to backend state)
- Building async translation pipelines

**Decision**: Leave as-is for v1. Can be addressed later via separate server-side i18n infrastructure if demand emerges.

### Log Stream Exclusion

The `/logs` panel displays real-time task logs from backend workers. These are deliberately excluded because:
- High-frequency mutations would overwhelm observer (performance cost)
- Logs contain structured data, stack traces, command outputs — often intentionally non-localized
- Users viewing logs expect raw technical information

**Exception**: Log stream prefix labels ("排程：", "状态:", "执行时间:") are translated as they're chrome, not log content.

### Future Scope

Later versions could address:
- Backend string keying (`qoder_tasks.py`, `qoder_scheduler.py` literals)
- Upstream provider metadata translation
- Plural forms (`1 个配额` vs `5 个配额`)
- Date/number formatting per locale
- RTL language support (Arabic, Hebrew)

These require expanding beyond the drop-in contract.

## 8. Testing

### Test Suites

#### `tests/_test_i18n_core.js`

**Environment**: Node.js, no DOM. Extracts L2 core block from `dashboard.html`, evaluates under `'use strict'`.

**Protected behaviors**:
- Tier-1 exact hit for simple messages
- Tier-2 pattern with reordered slots + nested slot value translation
- Tier-3 fragment with leading whitespace preservation
- Whitespace-collapse pass staying behind exact lookups
- Tier-4 identity fallback for unknown keys
- `t(non-string)` doesn't throw type errors
- `t(t(x)) === t(x)` observer termination idempotency
- Whole-pack rejection on malformed tier (others remain functional)
- `schedule()` flush when rAF never fires (hidden tab scenario)

**Why strict mode matters**: A sloppy `new Function` swallows `TypeError` from pattern caching bugs. Under strict mode, the bug aborts evaluation visibly instead of silently failing mid-document.

#### `tests/_test_i18n_route.py`

**Environment**: Real HTTP server on ephemeral port.

**Protected behaviors**:
- Manifest lists dropped file without server restart (plug-and-play contract)
- Path traversal attempts all return 404 (`..%2f`, `%00`, absolute paths)
- Non-`.json` names rejected (`.py`, `.txt`, extensions)
- Symlink escape via `realpath` check refused
- Route accessible without panel password (login gate requirement)
- Missing `i18n/` folder yields `{"packs": []}`, not 500 error

**Security focus**: Attacker-controlled path validation on unauthenticated route is the one item that must not be simplified.

#### `tests/_test_i18n_packs.py`

**Environment**: Validates all `i18n/*.json` files against pack contract.

**Protected behaviors**:
- Every file parses as valid JSON
- `@locale.code` matches filename exactly
- `@locale.version` is integer (cache invalidation signal)
- No key maps to itself (prevents infinite translation loops)
- No `{n}` slot in target absent from source pattern
- No catch-all pattern source (`{0}` alone)
- **Every `messages` key reachable from `dashboard.html`** (critical assertion)
- No value that's itself another key (breaks `t(t(x))` identity)

**Bug catching power**: Failed to spot five mistranscribed keys on first run — silent UI failures avoided.

#### Extended `tests/_test_dashboard_full_load.js`

**Protected behaviors**:
- `blocks[0]` remains theme script head block
- `blocks[length-1]` remains main script body block
- i18n block sits between them (block-order rule enforcement)

Silent block reordering broke two node suites previously — explicit assertions prevent regression.

### Browser Pass (Required)

Automated tests cannot detect these failures — manual browser verification is mandatory:

**Defects caught only in-page**:
1. `PAT[k].call` threw `TypeError` under strict mode → header translated, body stayed Chinese
2. rAF-only batching never flushes in hidden tab → entire page frozen untranslated
3. Slot values stayed source language → mixed-language sentences shipped
4. `TreeWalker(SHOW_ELEMENT)` skips root element → leaf text nodes missed
5. Stale `@locale.version` caused partial appearance → new keys looked broken

**Pass checklist**:
- [ ] Zero untranslated strings from `dashboard.html`
- [ ] 177 initial untranslated nodes → 36 after second content pass → 0 from source HTML
- [ ] Document title translated (head inaccessible to walker)
- [ ] Language button renders 34×32px immediately left of theme selector
- [ ] zh→en→zh round-trip through dropdown works
- [ ] Version-mismatch reloads don't loop
- [ ] No console errors or warnings
- [ ] Hidden tab edge case (background tab, wait 10s, foreground → translations appear)

**Measurement baseline**: English pack, auto-detect, no `?lang=` override. Body walk excluding `.log-line` and `.no-i18n`. SCRIPT/STYLE elements excluded.

### Regression Gate

Run full test suite before committing:
```bash
python tests/run_all.py
python scripts/check_clean_checkout.py
```

Second command ensures `i18n/` files committed, not left as untracked strays.

## 9. Troubleshooting

### Symptom: Stale Cache (New Keys Invisible)

**Problem**: Added 50 new translations to en.json, repeat visitors don't see them.

**Diagnosis**: Checked `@locale.version` — still at 1.

**Resolution**: Increment `version` to 2. Document requirement in pack author guidelines. Cache automatically refreshes on next page load.

**Prevention**: Make version bump mandatory in pack-update checklist.

### Symptom: Mistyped Key (Silent Failure)

**Problem**: Translator wrote `"数据分析看板"` instead of `"数据指标看板"` — key looks right but doesn't match.

**Diagnosis**: Console shows no errors (silent fallback to Chinese). `tests/_test_i18n_packs.py` catches this via reachability assertion.

**Resolution**: Run pack validation suite. Fix typo to match exact source string. Use automated extraction script rather than retyping.

**Prevention**: Extract keys programmatically from `dashboard.html`. Never hand-type keys.

### Symptom: Wrong Tier Assignment

**Problem**: Pattern should be in `messages` because it's static. Or fragment needs to be in `messages` because it's a complete sentence.

**Diagnosis**: Observe matching order confusion. More specific should be earlier tier.

**Resolution**: Move static complete sentences to `messages`. Keep only true fragments (space-prefixed suffixes) in `fragments`. Patterns only for runtime concatenation.

**Rule of thumb**:
- Complete static string → `messages`
- Space-prefixed piece → `fragments`
- Contains `{0}` slot → `patterns`

### Symptom: Pattern Order Issue

**Problem**: Shorter pattern matches before longer one, capturing incorrectly.

Example failure:
```json
{
  "patterns": {
    "{0} 天": " {0} days",           // Too general, listed first
    "近 {0} 天": "Within {0} days"     // Never reached
  }
}
```
Source: `"近 7 天"` → `" 7 days"` (wrong!) instead of `"Within 7 days"`

**Resolution**: List more specific patterns first. File order determines precedence.

**Prevention**: Group patterns by specificity. Longest/most-specific at top.

### Symptom: Mixed-Language Slots

**Problem**: `"颜色主题：跟随系统 (当前浅色)"` → `"Color theme: 跟随系统 (当前浅色)"`

**Diagnosis**: Slot values weren't recursed to depth 2.

**Resolution**: System already handles recursive slot resolution up to depth 2. Verify pack doesn't have catch-all pattern (`{0}` alone) which would bypass recursion guard.

**Root cause**: Catch-all pattern compiled to `^(.+)$` eats whole string, preventing slot lookup. Pack validator rejects this shape.

### Symptom: Malformed Pack (Page Breakage)

**Problem**: Invalid JSON, missing `@locale.code`, or other structural error breaks entire page.

**Resolution**: Should never happen — malformed packs must degrade to "no translations". If page breaks, investigate eval context (must be strict mode) and exception swallowing.

**Validation**: Pack suite rejects malformed files before deployment. Load-time wrapper wraps parse in try/catch.

### Debugging Steps

When i18n behaves unexpectedly:

1. **Check console logs**: Look for parse errors, TypeError, warning messages
2. **Inspect localStorage**: Verify `qd-i18n-pack` exists and contains valid data
3. **Test version mismatch**: Change `@locale.version` manually, confirm reload triggers
4. **Verify block order**: Use DevTools Sources to check script execution order
5. **Run pack validator**: `python tests/_test_i18n_packs.py` catches most issues
6. **Dry-run browser pass**: Test hidden tab, version bump, round-trip switching
7. **Check reachability**: Ensure every key exists in `dashboard.html`

### Common Pitfalls

| Pitfall | Impact | Prevention |
|---------|--------|------------|
| Missing version bump | Stale cache | Mandatory bump on every change |
| Hand-typing keys | Silent failures | Use extraction script |
| Catch-all pattern `{0}` | Infinite recursion | Pack validator rejects |
| Pattern order wrong | Over-capture | List specific first |
| Strict mode omitted | Silent crashes | Eval extracted core strictly |
| rAF-only batching | Hidden tab freeze | Always arm setTimeout fallback |

## 10. Implementation Notes

### Script Block Ordering

**Critical constraint from test suite**: `dashboard.html` currently has exactly two script blocks:
- `[0]` = Head/theme IIFE (lines 857–974)
- `[1]` = Main script (lines 1790–6306)

Test `tests/_test_dashboard_full_load.js` evaluates the last block and asserts `blocks[0]` is theme script.

**Placement rules for i18n additions**:
1. **L4 pre-paint bootstrap**: Append inside existing head block → `blocks[0]` remains theme script
2. **L2 core + L3 engine**: New third block placed **between** head and main script (just before `<body>` or just after `</header>`)
3. **Preserve invariant**: `blocks[0]` and `blocks[length-1]` both untouched
4. **Never append after main script**: Changes what the test evaluates, breaks stub assumptions

**Anchor safety**: New block must not contain literals used as `dash_extract` anchor (duplicated anchor mis-slices in extraction tool).

### Observer Re-entrancy

Writing `nodeValue` re-fires the MutationObserver. Termination guarantee:

**Mechanism**:
1. First pass: English translation written to text node
2. Observer fires again
3. Second pass: `QD_I18N.t(english_text)` called
4. English not in dictionary (keys are Chinese), hits tier-4 fallback
5. Returns input byte-identical → `out !== n.nodeValue` is false
6. Nothing written → observer stops firing

**WeakSet optimization**: `seen` cache makes early-return cheap (avoids second dictionary pass).

**Failure mode**: Pack whose `messages` key IS an English string that maps elsewhere causes infinite loop. Prevented by:
- Load-time validation rejecting self-referential keys
- `t(t(x)) === t(x)` identity requirement enforced in pack suite

### Performance Guards

Dashboard polls every 5 seconds and re-renders tables aggressively. Optimization layers:

**Memo Map (`MEM`)**: Each distinct source string resolved once per session. 500 text nodes displaying same label cost one lookup, not 500.

**Tier-2 gating**: Pattern matching only attempted if string contains digit OR length > 14. ~400 plain labels take fast path (exact lookup only). Patterns O(n) for concatenated sentences only.

**Batched flushing**: Observer callbacks batched in `requestAnimationFrame` with deduplication. Timeout fallback arms rAF for hidden tabs. Flush drains pending queue, nulls it — whichever callback wins, other returns immediately.

**Compiled regex cache**: Own `Map` separate from `PAT` objects. Cleared by `load()` on pack refresh. Never attach `PAT[k].call` property — in strict mode this throws `TypeError` and aborts mid-walk.

**Seen WeakSet**: Prevents re-walking unchanged subtrees. Node visited once per flush cycle.

**.log-line exclusion**: Removes highest-volume mutation source from cost model. Log stream churn doesn't trigger expensive walks.

### localStorage Budget

Estimated size per pack: 25–40 KB JSON. Browser quota typically 5 MB. Not a concern for reasonable pack sets.

Guard with try/catch around access:
```javascript
try {
  const cached = localStorage.getItem('qd-i18n-pack');
} catch (e) {
  // Quota exceeded or privacy mode — fall back to network fetch
}
```

Mirror pattern used by theme system (`getPref()`).

### Python 3.9 Compatibility

Backend code must run on Python 3.9 minimum. Constraints:

**Allowed features**:
- `%`-formatting (`"Hello %s" % name`)
- Basic comprehensions
- Dict/list literals
- `os.path.join`, `re.compile` standard libs

**Disallowed features**:
- `match`/`case` statements (3.10+)
- Type union operators (`X | Y`, 3.10+)
- `str.removeprefix()` / `str.removesuffix()` (3.9+)
- f-string expressions with `:` conversion (some forms)

**Migration note**: If upgrading Python floor later, these become available. Document current floor in `README.md`.

### Zero-Dependency Constraints

Frontend: Hand-written vanilla JS. No jsdom, no polyfills, no helper libraries. Tests use minimal DOM stub rather than `jsdom` to maintain this constraint's spirit.

Backend: stdlib-only Python. No Flask, no Django, no external packages. Existing `qoder_proxy.py` architecture respected.

**Rationale**: Single-file deployability. Users can drop files into folder and expect immediate work without `pip install` or `npm install`.

## 11. Glossary and Checklist

### Glossary

**Chrome**: UI framing elements (navigation, headers, footers) owned by the dashboard application, not backend data.

**DOM Boundary**: Point where server-rendered or JavaScript-composed strings enter the document tree. Translation happens here, not at source.

**Drop-in Contract**: Promise that adding `i18n/{code}.json` requires zero code changes. No registration, no rebuild, no restart.

**Identity Fallback**: Tier-4 behavior returning untranslated input byte-identically. Ensures nothing is ever blank or a raw key.

**L2 Core**: Layer 2 translation engine — pure JavaScript, no DOM. Exposes `QD_I18N.t()` function.

**L3 Engine**: Layer 3 DOM worker — TreeWalker, MutationObserver, text node updates.

**L4 Shell**: Layer 4 bootstrap — cache management, button rendering, manifest fetching.

**Mutation Observer**: Browser API watching for DOM changes. Fires callback when text nodes modified.

**Pat tern**: Regex template with slot placeholders `{0}`, `{1}`. Captures dynamic values from runtime-concatenated strings.

**Reachability**: Requirement that every `messages` key must exist somewhere in `dashboard.html` source. Ensures keys aren't phantom.

**Slot**: Positional placeholder in pattern (`{0}`, `{1}`). Captured group mapped left-to-right.

**Strict mode**: `'use strict'` JavaScript execution context. Throws on mistakes that sloppy mode swallows silently.

**TreeWalker**: Browser API iterating DOM tree hierarchically. Used for initial page walk.

**Version**: Integer cache invalidation signal in `@locale.version`. Increment on pack content change.

### Pack Author Checklist

**Before writing translations**:

- [ ] Run extraction script to identify all translatable strings

**Drafting the pack**:

- [ ] Set `@locale.code` matching filename
- [ ] Choose `@locale.name` in native script

- [ ] Start `@locale.version` at 1

- [ ] Avoid catch-all pattern (`{0}` alone)

**Validation**:

## Appendix: Quick Reference

### Adding a New Language (Minimal Viable Flow)

```bash
# 1. Create skeleton pack
cat > i18n/ja.json <<EOF
{
  "@locale": {"code":"ja","name":"日本語","dir":"ltr","order":20,"version":1},
  "messages": {},
  "patterns": {},
  "fragments": {}
}
EOF

# 2. Populate with extracted keys (manual or a throwaway script; no extractor is committed)
#    Translate the values, then merge into ja.json

# 3. Validate
python tests/run_all.py _test_i18n_packs

# 4. Test browser
python qoder_proxy.py
# Visit localhost:port/dashboard, select 日本語, verify

# 5. Commit
git add i18n/ja.json
git commit -m "i18n: Add Japanese support"
```

### Finding Translatable Strings

Run the repository's extractor (requires Node.js and the `acorn` package):

```bash
python scripts/extract_i18n_keys.py
python scripts/extract_i18n_keys.py --context 1-40   # print a slice with context
```

It walks `dashboard.html`'s HTML text runs and JavaScript string literals / concatenations and reports the Chinese strings not yet covered by `i18n/en.json`. A manual first pass is still possible with grep:

```bash
grep -oP '"[^"]{2,20}(?!"|\\")' dashboard.html | sort | uniq
```

Reachability is then enforced by `tests/_test_i18n_packs.py`: every `messages` key must appear in `dashboard.html` verbatim or after the whitespace-collapse pass.

### Common Error Messages

| Message | Meaning | Fix |
|---------|---------|-----|
| `TypeError: Cannot read property 'call' of undefined` | Pattern caching bug | Eval under strict mode, fix PAT[key] structure |
| `Stuck in translation loop` | Self-referential key | Remove key mapping to itself |
| `Missing @locale.version` | Malformed pack | Add integer version field |
| `Reachability failed: key not found in source` | Phantom key | Delete or move to dashboard.html |
| `Hidden tab freeze` | rAF-only batching | Arm setTimeout fallback |
